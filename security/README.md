# 研修管理システム セキュリティ本格対応（手順書）

## 目的
いまはデータベースが「公開状態（RLS無効）」で、アプリのアドレスと鍵を知っていれば
第三者がデータを閲覧・変更・削除できてしまう。これを **「ログインした人だけがアクセスできる」**
状態にする（Supabase Auth ＋ RLS）。Supabase からの警告メールもこれで解消する。

## 全体の段取り（安全のため段階的に。各段でテスト）
- [ ] **段階1：認証アカウントを裏で用意**（← 今ここ。本番アプリに影響なし）
  - `scripts/migrate-to-auth.mjs` を実行し、全職員＋ADMINを Supabase Auth に登録する。
- [ ] **段階2：ログインを正式認証に切替**（Claude が App.js を改修。RLSはまだOFFなので安全）
  - 従来の「全職員のパスワードをブラウザに読み込んで照合」をやめ、`signInWithPassword` に。
  - LINEログイン・職員追加/パスワード変更の連動用に、小さなサーバー処理を1つ追加。
  - デプロイして全ロール（職員/主任/管理者/LINE）でログイン確認。
- [ ] **段階3：RLSで施錠**（`security/enable_rls.sql` を実行＝本当の対策）
  - 動作確認後に実行。以後、未ログインの第三者はアクセス不可に。
- [ ] **段階4：後片付け**（平文パスワード列の整理、ストレージ(PDF)の権限、最終チェック）

## いま行う作業（段階1）

### 手順A：Secret（service_role）キーの取得
1. Supabase にログイン → プロジェクト **thc-study** を開く。
2. 左メニュー **Settings（歯車）→ API Keys**（または「API」）。
3. **`service_role` / Secret** の値をコピー。
   - ⚠️ **このキーは絶対に公開しない。チャットにも貼らない。** アプリのコードにも書かない。
   - （公開されている publishable/anon キーとは別物。管理者権限を持つ強力なキー。）

### 手順B：移行スクリプトを実行（PowerShell）
```powershell
cd C:\Users\heart42\kenshu-kanri
$env:SUPABASE_SECRET_KEY="ここに service_role/Secret キーを貼る"
node scripts/migrate-to-auth.mjs
$env:SUPABASE_SECRET_KEY=""   # 実行後に消す
```
- `完了：新規 ○ / 更新 ○ / スキップ ○ / 失敗 ○` と出れば成功。
- 「失敗」があれば、その職員のID/パスワードに空白や使えない記号がないか確認。

### 手順C（任意）：Auth の設定確認
- Supabase → **Authentication → Providers → Email** が有効になっていること（通常は既定で有効）。
- メール送信は行いません（アカウントは作成時に確認済みにしています）。

> この段階ではアプリは**従来どおり**動きます。裏で認証アカウントを用意しただけです。
> 完了したら Claude に「段階1おわった」と伝えてください。段階2（ログイン切替）に進みます。

## 重要な取り決め
- **ID→メール変換ルール**：`職員ID（小文字）@kenshu.thc-club.jp`
  （移行スクリプトとアプリのログインで**必ず一致**させる。変更しないこと。）

  上記スクリプト実行時の**一時的な環境変数**でのみ使用。ソースコードやチャットには残さない。
